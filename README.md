# TP-Link CT3CY 电信运营商定制版摄像头刷公版固件指南

> 本项目基于恩山论坛帖子整理：[原帖地址](https://www.right.com.cn/forum/thread-8494397-1-1.html)

闲鱼上大量的二手 **TP-Link CT3CY** 运营商定制摄像头（300万像素带云台），性价比极高。但原厂固件嫁割严重（小翼管家卡顿、广告多、无 ONVIF/RTSP、无 Web 页面）。

经外观与配置对比，CT3CY 与官方 **TL-IPC43AN-4** 硬件高度一致。通过刷入官方公版固件，可完美解锁 Web 管理、ONVIF、RTSP 拉流及本地 NVR 接入。

---

### 1. 硬件信息 (CT3CY V2.0)

- CPU: SSC325
- 传感器: SC3335
- Flash: 8MB
- 网口: 带网口（方便调试）
- 适配官方固件: TL-IPC43AN-4 V4.0 (支持 V1.0/V2.0/V4.0)

---

### 2. Flash 分区表

| 索引 | 分区名称 | 起始地址 (Offset) | 长度 (Length) | 结束地址 (End) |
|:---:|:---|:---:|:---:|:---:|
| 0 | Factory Boot (IPL) | 0x000000 | 0x02D800 | 0x02D800 |
| 1 | Factory Info (工厂参数) | 0x02D800 | 0x002800 | 0x030000 |
| 2 | Radio (IPL_CUST) | 0x030000 | 0x010000 | 0x040000 |
| 3 | User Config (加密 nvram) | 0x040000 | 0x020000 | 0x060000 |
| 4 | U-Boot | 0x060000 | 0x020000 | 0x080000 |
| 5 | TP Header | 0x080000 | 0x000200 | 0x080200 |
| 6 | Kernel | 0x080200 | - | - |
| 7 | Romfs (squashfs + xz) | Kernel End | - | 0x7E0000 |
| 8 | JFFS2 (overlay) | 0x7E0000 | 0x020000 | 0x800000 |

#### Factory Info 格式与 MD5 校验

本机 `backup.bin` 的 Factory Info 使用 `M1CT` 格式，不是“分区起始处 16 字节 MD5 + 长度”的布局：

- 分区范围：`0x02D800`–`0x02FFFF`。
- `0x02D800`–`0x02D803`：`M1CT` 标识。
- `0x02D804`–`0x02D807`：头部字节 `05 59 00 01`；本机有效载荷长度为 `0x0559` 字节，长度按实测载荷和 MD5 位置验证，不应把这 4 字节直接当作普通小端长度。
- 有效载荷从 `0x02D808` 开始，长度 `0x0559` 字节，范围为 `0x02D808`–`0x02DD60`（包含末尾 `}`）。
- 对上述有效载荷计算 MD5，16 字节原始摘要紧接其后，存放于 `0x02DD61`–`0x02DD70`。
- `0x02DD71` 之后为填充区。修改载荷字段后，必须重新计算并写回摘要；不要覆盖设备专属字段。

验证方法：计算 `MD5(flash[0x02D808:0x02DD61])`，结果应与 `flash[0x02DD61:0x02DD71]` 完全一致。Python 切片的结束偏移不包含在内。

### 3. 刷机步骤

> 提示: 上述步骤较繁琐，可将固件和需求交给 AI 自动完成打包。

1. 备份原机 8MB 编程器固件。
2. 从官网下载 TL-IPC43AN-4 V4.0 (如 20211105_1.0.28) 升级固件。
3. 从升级固件的 0x800 处截取 0x7A0000 字节，写入 Flash 的 0x60000。
4. 从升级固件末尾 ISP 数据区的 0x7B1084 处截取 0x58F0 字节，写入 Flash 的 0x30000。
5. 修改编程器备份的工厂分区（0x2D800 - 0x30000）：
- 将型号和版本号改为 TL-IPC43AN-4 和 4.0。
- 按上方 M1CT 格式重新计算有效载荷 MD5，并写回 `0x02DD61`–`0x02DD70`。
6. 刷机完成后，务必恢复一次出厂设置。

> 注意: 本步骁¤仅适合 CT3CY V2.0 硬件，其他版本切务盲目刷入，需自行分析研究。

### 4. 固件生成工具（Windows）

仓库提供 `firmware_builder.py` 图形工具，可通过文件选择框选择编程器备份、官方 TL-IPC43AN-4 V4.0 升级固件和输出位置。工具只生成固件文件，不会直接刷写设备，也不会修改输入文件。

#### 从 Python 源码运行

1. 安装带 Tkinter 的 Python 3.10 或更高版本。
2. 在仓库目录打开终端，运行：

   ```powershell
   python firmware_builder.py
   ```

3. 依次选择原机 8 MiB 编程器备份、官方升级固件(TL-IPC43AN-4_V4.0_1.0.28_Build_211105_Rel.50875n.bin文件是从官网下载的最新固件)和新固件保存位置。
4. 工具会验证备份的 M1CT 头部、有效载荷长度/结尾和原 MD5，以及官方固件的镜像头和 ISP 型号/版本标记。校验通过后，按上述分区偏移组装固件，修改 `devName`/`hwVer`，重算 M1CT 有效载荷 MD5，并验证写出文件。
5. 生成后请核对界面显示的输出路径和 SHA-256。刷机及恢复出厂设置仍需按本文前述步骤手动完成。

工具只支持本文记录的 CT3CY V2.0 / M1CT 布局。其他版本或布局不匹配时会停止，不应绕过校验强行生成。设备专属字段会从备份保留；不要分享含有设备标识或密钥的备份文件。

#### 可选：打包为 EXE

源码文件仍是完整、可检查和可直接运行的程序。若需要免安装运行，可在已安装 Python 的 Windows 环境中执行：

```powershell
python -m pip install pyinstaller
python -m PyInstaller --onefile --windowed firmware_builder.py
```

生成的程序位于 `dist\firmware_builder.exe`。PyInstaller 仅用于可选打包；如 Windows 显示未知发布者提示，应只运行自己从本仓库源码构建且信任的程序。

运行源码单元测试：

```powershell
python -m unittest discover -s tests -v
```

### 5. 功能流量与使用说明

- 本地流媒体: Web 页面一切正常，支持 ONVIF 和 RTSP 正常拉流，可完美对接本地 NVR。
- TP-LINK 物联 APP:
  - 本地模式: 不登录账号，可直接局域网发现并添加设备，一切正常。
  - 远程模式: 直接登录账号添加会失败（因服务器无该设备认证）。
  - 绕过方法: 在摄像头 Web 管理页面 -> 云服务 中，填写云账号和密码进行绑定，绑定后即可在 APP 远程查看。
- 实测功能: 公网 P2P 远程连接、人形识别、移动侦流均可正常使用。

> 提示: 未经服务器认证的设备能顺利打开 P2P 远程连接，这可能是一个官方 Bug，未来存在被 TP-Link 封堵的可能性。

Enjoy yourself !
